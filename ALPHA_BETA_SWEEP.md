# Matched alpha/beta sweep

Use a separately trained model for every `(alpha,beta)` pair. Evaluation always uses the same pair as training, so the experiment does not confound drift hyperparameters with a train/test SDE mismatch.

Recommended first experiment:

```bash
python scripts/run_alpha_beta_sweep.py \
  --pairs '1,1;1,3;3,1;3,3;4,3' \
  --max-epochs 1000 \
  --checkpoint-policy last \
  --sampler euler \
  --num-steps 50
```

The 2x2 subset `(1,1), (1,3), (3,1), (3,3)` separates the effect of alpha from beta. `(4,3)` is the paper-like reference setting.

For a faster pilot, set `--max-epochs 100 --root sweeps/alpha_beta_pilot`.

For replication across seeds:

```bash
python scripts/run_alpha_beta_sweep.py \
  --pairs '1,1;1,3;3,1;3,3;4,3' \
  --seeds 0,1,2 \
  --max-epochs 1000
```

Outputs include per-run and seed-aggregated CSV files plus plots of latent SI-SDR, source-image SI-SDR, failure rate, measurement residual, and nMSE.

`--checkpoint-policy last` is the default because this is a matched fixed-training-budget ablation. Use `best` only if the intended protocol explicitly selects every model by the same validation criterion.

## PyTorch 2.6+ checkpoint loading
`evaluate.py` explicitly passes `weights_only=False` to Lightning's
`load_from_checkpoint`. The project checkpoints include Hydra/OmegaConf metadata,
so PyTorch 2.6+'s `weights_only=True` default rejects them. Use this only for
checkpoints you trust, such as checkpoints generated by this training code.
